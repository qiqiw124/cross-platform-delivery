# Maintenance

## Shared Spec 什么时候更新
- 业务规则变化
- 字段定义变化
- 状态机变化
- 埋点来源变化
- 多仓库归属变化
- 验收标准变化

## Repo Spec 什么时候更新
- 仓库内实现路径变化
- 生命周期处理变化
- 缓存/线程/容错逻辑变化
- 本地埋点或状态处理变化

## 推荐维护方式
- 先更新 shared spec，再更新各仓库 repo spec
- 若只是单仓库实现调整、不影响跨端口径，只更新 repo spec
- 若联调结论改变了业务口径，shared spec 与 repo spec 都要更新

## 最小维护原则
- 不写大而全总结
- 只记录“当前有效规则”和“当前实现约束”
- 始终保留：字段口径、状态口径、埋点来源、回归路径
